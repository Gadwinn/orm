EntityTrait

EntityTrait.php : 44

Optional active-record style convenience helpers for entities.

Using this trait keeps entities pure POPOs: there is no base class, no injected manager, and no tracking state. The trait resolves the active DbManager dynamically through OrmRegistry, so the same entity works in any runtime that has bound a manager to the current context.

Persistence always flows through the manager's Unit Of Work pipeline. save() and remove() never issue SQL directly, so snapshots, change detection and transactions stay unified with the rest of the ORM.

Relation-hydration guideline:

Relations remain explicit - the trait provides no magic loading. Write relation accessors by hand as concise wrappers around a registry-resolved repository, using the protected orm() helper:

public function address(): ?Address
{
    return $this->orm()->repository(Address::class)->find($this->addressId);
}

// HasMany returns the rows for the inverse side explicitly:
public function orders(): array
{
    return $this->orm()->repository(Order::class)->findBy(['customer_id' => $this->id]);
}

Keep such methods minimal, predictable and fully visible; never hide a query behind property access.

QueryBuilderInterface
in
  • Application

QueryBuilderInterface.php : 24

SQL-first, fluent query builder.

The builder structures SQL; it does not hide it. It is fully independent from the entity/mapping layer and is usable on its own. Terminal methods return plain associative-array rows (or an affected-row count for write statements); hydration into entities is the repositories' concern.

Two predicate styles are supported on where():

  • manual: ->where('id', '=', 1)
  • expressive: ->where('age')->gt(18)

In the expressive form the builder delegates the comparison vocabulary to a QueryExpressionClauseInterface and never implements that fluent API itself.

from()

QueryBuilderInterface.php : 45

Set the target table(s) for SELECT and DELETE statements.

public from(string ...$tables) : static

Variadic to support multi-table statements (e.g. a multi-table DELETE: "DELETE t1, t2 FROM table1 t1 JOIN table2 t2 ..."). For raw tables, aliases are expressed inline within each entry ('users u'). For a mapped entity class, an alias may be supplied as the immediately following argument (from(User::class, 'u')); it defaults to the table name. The first mapped entity becomes the active context for entity-style joins and SELECT-driven eager hydration.

UPDATE and INSERT do not use from(): they declare their target table up front through update() and insert().

public join(class-string|string $tableOrEntity[, string|null $aliasOrCondition = null ]) : static

Dual mode: pass a raw table name together with an explicit ON condition, or pass a mapped entity class so the builder resolves the table and keys from relation metadata. For an entity join the second argument is the join's SQL alias (defaulting to the table name); for a manual join it is the required ON condition. Manual joins always remain available.

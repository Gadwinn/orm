Snapshot-based Unit Of Work.

Three intentions are tracked by instance: pending inserts, pending deletes and the managed set (persistent entities with an original-state snapshot). Updates are never stored as an intention: there are no dirty flags. At flush time every managed entity's current state is diffed against its snapshot and only the changed, non-key columns are written.

Entities are keyed by spl_object_id() so identity is by instance, never by value. Partial hydration is honoured through per-entity loaded-field masks: a column absent from the mask is "unknown" and never diffed, which prevents phantom updates from never-loaded columns.

A dual-layer lifecycle wraps each write. Internal hooks — methods flagged with the #[Before*]/#[After*] attributes — always fire; an optional PSR-14 dispatcher additionally emits the matching events. For updates the pipeline is synchronised: the user-driven Changeset is handed to #[BeforeUpdate] hooks, the entity is then re-diffed so columns the hook mutated join the SET clause, and only that final change set is dispatched and written. Hooks for a managed entity fire only when it actually has pending changes.

Hook discovery is reflection-based but paid for once per class: the first row of a type is scanned and its lifecycle methods indexed by attribute into self::$hookCache; every subsequent row of that type runs straight from the cache without touching reflection again.

register()

UnitOfWork.php : 165

Register an already persistent entity as managed.

public register(object $entity, int|string|array<string|int, mixed> $id[, array<string|int, mixed>|null $loadedFields = null ]) : void

Used by repositories after hydration: the entity is added to the Identity Map and its original-state snapshot is captured so that subsequent changes can be detected.

For partial hydration, $loadedFields lists the property names that were actually populated by the query (the primary key is always implied). The snapshot is masked to those fields and change detection ignores any field outside the set. Passing null marks the entity as fully hydrated.

A field absent from $loadedFields is "unknown" and is never diffed; a field present in $loadedFields whose value is null is a real database NULL. This structural distinction prevents phantom updates.

executeUpdates()

UnitOfWork.php : 407

Execute pending UPDATEs through the synchronised hook pipeline:

private executeUpdates(array<int, array{objectId: int, table: string, changes: array, where: array}> $updates) : array<int, array{objectId: int, current: array}>
  1. Hand the user-driven change set to #[BeforeUpdate] hooks.
  2. Re-diff the entity so any column a hook mutated (e.g. an audit timestamp) joins the SET clause.
  3. Dispatch BeforeUpdateEvent with that final change set.
  4. Write the row, then run #[AfterUpdate] hooks and dispatch AfterUpdateEvent.

Returns the post-flush snapshot for each touched entity.

$updates : array<int, array{objectId: int, table: string, changes: array, where: array}>

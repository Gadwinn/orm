UnitOfWorkInterface.php : 27

Coordinates entity persistence.

The Unit Of Work owns three logical queues (insert / update / delete), the Identity Map and the original-state snapshots used for change detection.

Change tracking relies exclusively on normalised snapshot arrays taken when an entity becomes managed. No dirty flags, no tracking properties and no entity inheritance are involved. At flush time the current state of every managed entity is compared against its snapshot and only the modified columns are written.

Partial hydration is supported. When an entity is hydrated from a partial column selection, the snapshot records which fields were actually loaded (state masking). Change detection then compares only those loaded fields; fields skipped during hydration are ignored unless the developer explicitly initialises or modifies them. The primary key is always part of the loaded set so the entity can be tracked.

register()

UnitOfWorkInterface.php : 66

Register an already persistent entity as managed.

public register(object $entity, int|string|array<string, scalar> $id[, array<int, string>|null $loadedFields = null ]) : void

Used by repositories after hydration: the entity is added to the Identity Map and its original-state snapshot is captured so that subsequent changes can be detected.

For partial hydration, $loadedFields lists the property names that were actually populated by the query (the primary key is always implied). The snapshot is masked to those fields and change detection ignores any field outside the set. Passing null marks the entity as fully hydrated.

A field absent from $loadedFields is "unknown" and is never diffed; a field present in $loadedFields whose value is null is a real database NULL. This structural distinction prevents phantom updates.

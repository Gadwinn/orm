DbManager.php : 32

Central orchestration hub and primary entry point of the ORM.

It wires the connection, metadata, hydrator and Unit Of Work together and exposes the four usage levels: raw SQL, query builder, repositories and Unit Of Work writes. Repositories are instantiated lazily and cached per entity class. The identity map is owned by the Unit Of Work and reached through it, so a single instance backs the whole manager.

flush()

DbManager.php : 116

Synchronise all pending changes with the database.

public flush() : void

Inserts, updates (modified columns only) and deletes computed by the Unit Of Work are executed. This does NOT commit an SQL transaction.

Lifecycle rule: flush() may be called several times inside a single transaction block before commit() or rollBack() is invoked. When no transaction is active, a flush() applies its changes to the database immediately.

purgeStaleState()

DbManager.php : 182

Purge in-memory state after a database rollback.

private purgeStaleState() : void

A rollback reverts the database but leaves the PHP entities holding their mutated, now-uncommitted values. Detaching every managed entity (which also empties the identity map) forces the next operation to re-fetch clean rows, eliminating the memory-vs-database desync.

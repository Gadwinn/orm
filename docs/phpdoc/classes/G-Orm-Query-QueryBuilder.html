QueryBuilder.php : 35

Concrete SQL-first query builder.

It accumulates a mutable QueryState while the developer chains calls, then delegates compilation to a SqlCompilerInterface and execution to a ConnectionInterface on the terminal methods.

By default the builder is mapping-independent and only supports manual joins (explicit ON condition). When constructed with a metadata reader it also supports entity-style joins: calling from() with a mapped entity class resolves its physical table and records it as the active entity context, so a later join() on a related entity class can resolve the target table and the "local.localKey = target.foreignKey" condition from relation metadata.

from()

QueryBuilder.php : 136

Set the target table(s) for SELECT and DELETE statements.

public from(string ...$tables) : static

Variadic to support multi-table statements (e.g. a multi-table DELETE: "DELETE t1, t2 FROM table1 t1 JOIN table2 t2 ..."). For raw tables, aliases are expressed inline within each entry ('users u'). For a mapped entity class, an alias may be supplied as the immediately following argument (from(User::class, 'u')); it defaults to the table name. The first mapped entity becomes the active context for entity-style joins and SELECT-driven eager hydration.

UPDATE and INSERT do not use from(): they declare their target table up front through update() and insert().

getEntities()

QueryBuilder.php : 408

Execute the SELECT and ventilate each flat row into hydrated entities.

public getEntities() : array<int, object>

This is the SELECT-driven eager-loading terminal. There is no with(), no proxy and no lazy loading: which related entities are hydrated is decided strictly by the columns present in the result set.

  • When the select is empty or a bare "*", it is expanded to every registered entity's columns, alias-prefixed ("u.id AS u__id") so the joined datasets never collide under PDO's associative fetch.
  • Each row is split per alias; the root entity is hydrated once per identity (enforced through the identity map) and each joined entity present in the row is injected into its matching relation property.
  • A joined entity whose columns are absent from the select is ignored entirely: the relation property is left untouched, never lazily fetched.

Every hydrated entity (root and joined alike) is registered with the Unit Of Work, so it is change-tracked exactly like a repository-loaded one: mutate it and the next flush() writes the diff.
